# 码道提示词手册（完整版）

> RAGGO!!!!! ｜ 用法：每个任务单独开一个码道会话，按顺序贴对应提示词
> 通用原则：**Prompt 三要素 = 上下文（什么项目）+ 约束（字段/规范/不引框架）+ 验收（怎么算完成）**
> 铁律：产物中不出现任何第三方 AI 工具痕迹；叙述中 AI 工具只提"华为云码道 CodeArts"

---

## 0. 开场必做：项目认知（每次新会话先发这条）

```
请先了解我的项目：这是一个面向珠海科技学院学生的校务生活 RAG 问答平台
（爬虫采集官方通知 → 混合检索 → 大模型生成带出处的回答）。
请阅读 README.md、crawler/、retrieval/、api/、miniapp/ 的代码，输出：
1) 各模块职责简述
2) 当前检索链路（关键词路 → 语义路 → RRF → 重排 → 时效降权）
3) 你发现的待完成事项或代码问题
只分析，不要修改任何文件。
```

## 3. 生成层：Prompt 与回答质量（ZY）

### 3a. 生成 Prompt 优化

```
api/llm.py 中 SYSTEM_PROMPT 是当前的大模型系统提示词。
请优化它，目标是：
1) 回答更口语化，像学长回答学弟，不要官腔；
2) 数字/时间/电话必须与参考内容逐字一致；
3) 参考内容不足以回答时，明确说"通知里没写"并建议联系对应部门；
4) 保持引用出处的习惯（在句末用（来源：标题）标注）。
输出优化后的完整 SYSTEM_PROMPT。
```

## 5. 应用层：小程序对接（ZC 用）

### 5a. 对接问答接口

```
miniapp/pages/index/index.js 当前是静态占位。
请把它对接到后端问答接口：
1) POST http://127.0.0.1:8000/ask，请求体 {"question":"...","topk":3}；
2) 响应字段：answer（答案）、confidence（置信度 0-1）、
   references（数组，含 title/department/source_url）；
3) 首页搜索框提交后跳转 result 页展示答案与出处列表，
   出处点击用 web-view 或复制链接；
4) 请求失败时给友好提示（检查服务是否启动）；
5) 接口地址做成可配置（顶部常量，开发环境 127.0.0.1:8000）。
```

### 5b. 结果页美化

```
miniapp/pages/result/ 当前是基础列表。
请优化为：答案卡片（含置信度进度条）+ 出处列表（带部门标签和跳转）
+ 加载骨架屏 + 空结果状态。样式与 index 页保持一致的蓝色系。
```

## 6. 评测：扩容与回归（HJQ 辅助，ZY 执行）

### 6a. 评测集口语化扩容

```
evaluation/questions.csv 当前 40 问，全是题库式问法（与文档标题近似）。
请基于 data/clean/ 里 199 篇通知的真实内容，补充 30 个口语化问题，
要求：
1) 问法像学生随口问："空调坏了找谁修""四六级啥时候报名"；
2) 每题给出期望命中的通知 id 和关键词；
3) 类别沿用现有分类（教务-通知/后勤-生活/招生-政策等）；
4) 直接输出可追加到 CSV 的行。
```

### 6b. 评测报告分析

```
把 evaluation/ 最近一次评测的输出结果发我（或粘贴 runner 输出），
请分析：1) 失败/低置信度的题目集中在哪些类别；
2) 每道失败题的可能原因（未召回/排序错/生成跑偏）；
3) 按性价比给出 3 条修复建议。
```

## 附：拿分要点与纪律

1. **一个任务一个会话**——对话记录清晰，留痕材料好整理
2. **每完成一个任务**：截图对话 + 运行结果 → `submission/codearts_proof/week2-冲刺2/`
3. **码道改完的代码**：本地 `python -m pytest tests/ -q` 跑过再提交
4. **Prompt 别写一半**：三要素凑齐才值"Prompt 设计质量"分
5. 产物中不出现任何第三方 AI 工具痕迹；叙述里 AI 只提"华为云码道 CodeArts"
