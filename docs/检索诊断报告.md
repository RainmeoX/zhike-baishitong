## 三、根因分析

### 根因 1（主因）：空内容附件页走 0.8×RRF 高权重路径

`retrieval/hybrid.py` 对空内容文档采用 `blended = 0.2×rerank + 0.8×rrf_norm`。库内核验确认登顶文档全部为空内容页（content_len=0，正文在附件图片/PDF 中未爬取）：

| 文档 | content_len | 发布日期 | recency |
|------|:---:|------|:---:|
| [188071] 兼职教师住宿管理规定 | 0 | 2026-06-24 | 1.0 |
| [188121] 建筑施工安全事故应急预案 | 0 | 2025-11-28 | 0.75 |
| [178949] 校内日常服务电话 | 0 | 2026-04-29 | 1.0 |
| [178948] 校内各类故障报修办法 | 0 | 2026-04-29 | 1.0 |

这些页面标题含查询同义词（住宿/规定/安全/预案），关键词路排名高 → rrf_norm≈1.0 → blended≈0.8，重排分近零（0.0001~0.017）也无妨。**但正文为空，实际无法回答问题，却稳定登顶。**

### 根因 2：时效降权 0.5 档砍半制度类长期有效文档

正确答案文档多为 2 年以上老通知（水费办法/就餐须知/卫生规定/用电预案），recency=0.5。以 Q8 为例：`(0.65×0.9907 + 0.35×1.0) × 0.5 = 0.497`，被空内容页的 0.8 碾压。制度/办法/预案类文档长期有效，0.5 档过狠。

### 根因 3（Q1 特例）：正确文档本身是空内容页，重排器失准

Q1 的正确文档 [178949]/[178948] 本身 content_len=0，重排器只能拿到「标题+标题+部门+栏目」拼接文本，无法评估相关性（rerank 0.006/0.0008）；而有 884 字正文的节日通知 rerank 0.824 登顶。这是**数据层问题**：报修电话列表、报修流程等关键内容在附件中未爬取。

### 根因 4（评测层）：判定文本拼入 LLM 回答，MRR 失真

`evaluation/runner.py` 第 97 行 `ref_text = answer + " " + title`（Recall@K 同，第 107-109 行）把 LLM 回答拼进判定文本——只要回答里含期望关键词，hit_rank 必为 1，MRR 恒为 1.0，**掩盖了检索层 top-1 错配**。评测指标无法反映真实检索质量。
